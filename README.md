# finance-design — React-прототип

Самостоятельный исследовательский репозиторий в `finance-app/research/`. Он не входит в `app/finance-client` и не подключён к общему деплою приложения.

Актуальные брендбук, UI Kit, 172 мобильных состояния, 25 сценариев и настольный концепт находятся в одном React-проекте. Визуальный эталон — первый HTML-прототип (`research/design/index.html`, `styles.css`, `prototype.js`); 45 состояний связаны с файлом [Figma](https://www.figma.com/design/ch4sqQeEeTasSQ7Bh6bEz8?node-id=0-1), остальные расширяют концепт по полному каталогу ФТ и ТЗ. Макет кликабельный, но не выполняет финансовых операций.

В мобильном просмотре можно выбрать валюту первого счёта (по умолчанию USD), переключать расход/доход/перевод в одной форме, открыть калькулятор нажатием на сумму (есть клавиша `000`), выбрать валюту и увидеть предварительный пересчёт. Экран валют поддерживает ручной курс, добавление кода валюты и обновление по API Frankfurter. Есть интерактивные экраны мультивалютного счёта, отчёта по категориям и месячного бюджета. Их денежные данные демонстрационные.

Раздел «Экраны» сразу открывается в режиме просмотра на весь браузер. Телефон показывается в размере 100%, а область просмотра прокручивается, если места не хватает; кнопка «Вписать телефон» включает уменьшенный обзор. Быстрые вкладки переключают базовый поток, выпадающий список содержит все 172 мобильных состояния по модульным группам, стрелки и клавиши ← → переходят к соседним. Кнопка «К разделам» возвращает к обычной странице. Переход между экранами не сбрасывает прокрутку страницы.

## Локально

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`). Для проверки готовой сборки:

```sh
npm run build
npm run preview
```

`index.html` следует открывать через сервер, а не двойным кликом через `file://`: браузер блокирует ES-модули на локальном файловом протоколе.

## Docker

Из корня репозитория:

```sh
docker build -t finance-design-react .
docker run --rm -p 8080:80 finance-design-react
```

Откройте `http://localhost:8080`. Dockerfile собирает Vite-приложение на Node.js и отдаёт статические файлы через Nginx. Hash-маршруты позволяют открыть экран напрямую, например `http://localhost:8080/#screens/options`.

## Структура

| Путь | Назначение |
|---|---|
| `src/components/ui.jsx` | Общие React-компоненты дизайн-системы |
| `src/components/Phone.jsx` | Мобильный макет, собранный из этих компонентов |
| `src/components/FinanceFlows.jsx` | Интерактивные сценарии операций, валют, счетов, отчёта и бюджета |
| `src/pages/` | Brandbook, UI Kit, Экраны, Сценарии, Документация |
| `src/data/` | Содержание 54 состояний и маршруты из исходных макетов |
| `src/styles.css` | Токены и оформление компонентов |
| `DECISIONS.md` | Обоснование решений и ограничения |

Проверка карты экранов и переходов: `npm run check`. Проверка компиляции: `npm run build`.

## Настольный концепт

Раздел `Desktop` (`#desktop`) показывает настольную компоновку с группами разделов и иконками. «Бюджет» вынесен в отдельный раздел с лимитами, расходами и переходами к настройке и порогам. Боковая панель содержит быстрые входы в основные мобильные модули, а «Все функции» (`#desktop/catalog`) позволяет найти и открыть в настольной компоновке каждое из 172 состояний мобильного каталога. Финансовые действия в концепте остаются демонстрационными.

Новая операция и отчёты в Desktop используют те же интерактивные компоненты, что и мобильная версия: переключение расхода, дохода и перевода, калькулятор суммы, выбор счёта и категории, круговую диаграмму и переход к операциям категории. Настольная компоновка меняет только расположение этих элементов.

## Дополнения по повторному ревью

Добавлены интерактивные состояния разделения операции (поровну, проценты, доли, позиции; расход и доход), очереди проверки OCR/дублей, приглашения в поездку, покупки «распределить позже», завершения поездки и объяснения правила. В Desktop появились переносимая книга, локальное напоминание, горячие клавиши и передача изображения. Все действия остаются демонстрационными.

## Чек и QR

В мобильной форме «Новая операция» при выбранном типе «Расход» находятся кнопки «Фото чека» и «QR чека». Экраны позволяют выбрать изображение и перейти к демонстрационной проверке. Реальное OCR, декодирование QR и получение фискальных данных в UI-концепте не подключены.
